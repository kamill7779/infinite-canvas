# 待测试

- 服务端画布 Agent：右侧仅保留统一 Agent UI，无本机/云端模式切换；登录后可新建会话、多轮对话，工具在浏览器内执行并可开关“工具确认”。
- 服务端画布 Agent：普通闲聊（plain chat）不应进入画布工具循环；涉及读写画布时才触发工具调用与确认。系统提示已明确问候/无需画布操作时用纯文本回答；后端不强制 `tool_choice=required`。
- 服务端画布 Agent：同一只读工具+同一参数连续静默调用 2 次应停止；`get_state`→`get_selection`→写 等合法读两次再写不应被误杀。
- 服务端画布 Agent：上游非 2xx 若返回 HTML 错误页，应看到带 title/摘要的短错误而非整页 HTML；JSON `error.message` / `request_id` 优先展示。
- 服务端画布 Agent：多画布 tab / 多会话时 agent.* 事件按 sessionId/canvasId 过滤，工具写操作不得串到错误画布；tool-result 必须带 sessionId。
- 服务端画布 Agent：收起侧栏不卸载 WS；进行中 turn 的 tool_call 与确认卡仍可处理；`stopped` 状态应展示停止原因，而非仅显示「完成」。
- 服务端画布 Agent：canvas-state / tool-result 失败应有错误提示，不得静默当成功。
- 服务端画布 Agent：断线重连后会话与消息可恢复；拒绝/确认工具、撤销上一次工具写入行为符合预期。

- Codex 插件 / open-canvas 技能：只打开 `mode=new|recent|choose` 画布 URL，不再启动 `npx @basketikun/canvas-agent`，不再拼接 `agentUrl`/`agentToken`；打开后引导使用页内 Agent。
- 产品文档：功能介绍与 Codex 插件文档已去掉本机 Agent 路径说明；历史 CHANGELOG `v0.3.0` 条目可保留。
- Codex App 插件文档：新增插件安装教程，区分 AI 自动安装、手动安装和本仓库开发调试安装；同步优化插件 README 与技能说明。
- 配置与用户偏好：每个模型渠道新增 OpenAI / Gemini 调用格式选择，默认 OpenAI，切换默认格式时同步更新默认 Base URL；渠道 Tab 增加紧凑醒目的提醒，说明模型是否可选需要到“模型”Tab 选择。
- Gemini 调用格式：支持拉取 Gemini 模型列表，并用于文本问答、在线 Agent 工具调用、基础生图和图生图请求。
- 音频和视频生成：选择 Gemini 调用格式时先给出不支持提示，仍需使用 OpenAI 兼容渠道。
- 商业化后台：模型定价与渠道名建立数据库外键关系，渠道改名后定价行应自动同步；定价保存和渠道重名需要验证错误提示是否友好。
- 图片生成异步队列与 WebSocket 推送：`/api/generate/image` 改为预扣+入队即返回（不再同步等上游），由独立 worker 进程（BullMQ）消费生成、落 R2、结算/退点，结果经 Redis Pub/Sub → 独立 WebSocket 网关（`/api/generate/events`）推送到前端 slot；断线经 `GET /api/generate/image/:id` 补偿。**需真实 Redis + 独立 worker + WS 网关三进程**，本地 `docker compose -f docker-compose.local.yml up --build`（或 `bun run worker:image` / `bun run ws:events` 分别起后端进程）。反向代理需透传 WS 的 `Upgrade`/`Connection` 头。尚未做生产压测验证，仅完成实现与本地联调项。
- Go 后端图片生成队列硬化：生成记录状态更新增加终态 CAS，失败退点避免覆盖成功记录；worker 抢不到用户/渠道并发槽时改为等待槽位而不是消耗业务重试，并用 Redis owner-token 信号量避免误释放；兜底对账只处理已启动且超时的 running 记录，避免误退正常 pending 任务。需用真实 Redis/PostgreSQL/Worker 做并发提交、失败重试、对账退点和 WebSocket 事件回填验证。
- 画布图片生成轮询：画布旧调用的图片任务等待窗口已对齐后端 worker 兜底对账窗口，避免后端稍晚成功时前端先把节点标记为“生成超时”。需在画布一次生成多张图片时验证全部成功图片都能回填，且真正失败/退点任务仍显示失败。
- Docker Go 分离部署与 R2 存储：本地 Go 分离架构已可通过 R2 环境变量启用 Cloudflare R2，新生成图片应上传到 R2；seed 在默认渠道被后台改名后应继续使用现有渠道名写入定价，避免重启时外键失败。需在真实生图后到 R2 bucket 与前端画布同时确认图片可访问。
- Docker Go 分离部署：seed 仅在默认渠道不存在时初始化 `seed-default`，重新部署不应覆盖后台已保存的默认渠道 Base URL 和 API Key。
